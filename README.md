# HOMG0 局域网联机 Demo

端口：37788

## 人机对战

创建房间时可以选择“人机对战”，并选择自己控制的阵营。机器人自动控制另一阵营，房间创建后立即开始。

大厅只显示房间列表和创建界面，不会提前创建或显示棋盘。创建或加入房间并收到房间状态后，客户端才根据服务器下发的棋盘描述生成棋盘。

创建房间页面先选择“战役模式”或“对战模式”；战役模式暂未实现并禁用，对战模式下通过“模式”下拉选择具体玩法，当前为“经典模式”。“与人机对战”不再作为独立对战模式，而是位于默认折叠的“游戏参数”中，默认关闭；勾选后才会显示机器人难度。增援量与双方兵种上限分别收在“进攻方兵力设置”和“防守方兵力设置”中，并与“部署规则”一起统一放入“游戏参数”。

对手类型（玩家/机器人）与玩法模式使用不同字段：`gameMode` 表示对手类型，`variantId` 表示玩法。服务端从 `data/variants.json` 加载玩法注册表，再读取每个玩法绑定的地图、单位和规则文件；状态中会下发 `variantId`、`boardId`、玩法信息和完整地图描述。地图描述包含棋盘尺寸、格子、格子属性、部署行以及格子连接关系；前端不内置地图，也不会从旧数据猜测或补齐地图，缺少合法地图时只清空棋盘并等待服务端发送合法状态。当前只登记 `classic`；未知或未启用玩法会安全回退到经典模式。新增玩法若改变移动、射击或胜负规则，应提供对应的序列化规则和引擎能力声明；不支持的机器人能力会被服务器拒绝，不会误用经典机器人策略。

单位定义和游戏规则同样由服务端随房间状态下发到 `rules` 字段。该字段包含单位名称、图标、移动/射程参数、单位免疫关系、地形可通行单位、地形攻击免疫、战斗和回合规则等。服务端同时计算并下发每个单位的 `selectable`、`legalMoves`、`legalShots` 以及当前玩家的 `legalDeployments`；前端只使用这些结果进行高亮和交互，不自行计算可选定、移动或攻击范围。移动、部署、射击、地形限制和胜负判定始终由服务端再次校验。规则缺失或格式非法时，前端不自行恢复规则，只显示安全的未知单位/地块占位并等待合法状态。

地图、单位和规则不是写死在核心代码中的定义，而是以可读 JSON 存放：

```text
data/
├── maps/classic.json   # 地图尺寸、行/格子、地形、连接邻接表
├── units/classic.json  # 单位名称、图标、移动、射程、行动规则
├── rules/classic.json  # 地形通行/免疫、战斗、胜利和回合规则
└── variants.json       # 玩法与地图、单位、规则文件的绑定
```

服务端启动时会读取、校验并规范化这些文件；运行时通过 `serializeDefinition` / `deserializeDefinition` 支持 JSON 文本与对象互转，`normalizeBoardDefinition`、`normalizeUnitsDefinition`、`normalizeRulesDefinition` 负责兼容旧式数组/对象结构并过滤非法字段。自定义内容只需复制对应 JSON 并在玩法注册表中登记，核心房间和前端代码即可继续使用同一套状态契约。

机器人采用后端轻量效用评分，不进行 Minimax、MCTS 或神经网络搜索。它会优先执行立即获胜和即时击杀，并综合考虑集火、进攻推进、防守封锁、堡垒与楼梯、后续射击机会、机动空间和敌方火力威胁。部署阶段会根据场上兵种和位置选择单位，并在低增援时保留少量后备。

难度分为三档：

- **简单**：在多个较高分动作中随机选择，忽略大部分站位风险。
- **普通**：在接近最优的动作中选择，并考虑基本威胁。
- **困难**：选择当前评分最高的动作，更重视敌方射程和机动空间。

所有难度都只评估当前合法动作，每个动作后重新读取局面，并通过定时器让出事件循环。单个机器人回合最多执行100步，避免极端自定义配置拖住服务器。

运行 `npm test` 可以检查机器人关键策略和前端脚本语法。

## 可选音效

音效目录位于 `public/audio/`。没有对应文件则不播放；同一目录有多个支持格式的文件时随机选择。

支持：`.mp3` `.wav` `.ogg` `.m4a` `.aac` `.webm` `.flac`

游戏结束音乐从 `public/audio/end/` 随机读取；当前示例文件为 `game-over.mp3`。游戏结束后会停止普通背景音乐并播放一次结束音乐。

对局中的“退出房间”会结束当前对局并将当前客户端返回大厅；另一方会收到对应的胜利状态。对局结束后，结果显示在棋盘下方横幅中，不再使用全屏结果弹窗。

## 同时回合制

经典模式可以在创建房间的“游戏参数”中启用同时回合制，默认关闭。双方在规划阶段分别保存部署、射击和移动计划；双方提交后，服务器按照“部署→同时射击→移除死亡单位→同时移动→胜负判定”结算。部署冲突和移动路径的中间格/最终格冲突都由服务器逐点随机决定，失败移动回到原点。具体能力和超时设置位于 `data/rules/classic.json` 的 `simultaneous` 节点，详细状态与扩展约定见 `docs/simultaneous-turns.md`。

机器人在自己的回合开始行动前，会像玩家一样连续部署所有当前合法且可用的单位，然后再执行移动和射击。开启“允许行动后部署”只会放宽玩家/机器人在行动后的部署限制，不改变机器人会优先完成部署阶段的行为。

```text
public/audio/
├── bgm/                         # 背景音乐，可放多个文件
├── move/
│   ├── infantry/                # 步兵移动
│   ├── anti-tank/               # 反坦克炮移动
│   └── machine-gun/             # 机枪车移动
├── attack/
│   ├── infantry/                # 步兵攻击
│   ├── anti-tank/               # 反坦克炮攻击
│   └── machine-gun/             # 机枪车攻击
└── death/
    ├── infantry/                # 步兵死亡
    ├── anti-tank/               # 反坦克炮死亡
    └── machine-gun/             # 机枪车死亡
```

浏览器通常禁止未经过用户操作的自动播放，因此背景音乐会在玩家第一次点击、触摸或按键后开始。
