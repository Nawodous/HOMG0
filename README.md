# HOMG0 局域网联机 Demo

端口：37788

## 人机对战

创建房间时可以选择“人机对战”，并选择自己控制的阵营。机器人自动控制另一阵营，房间创建后立即开始。

大厅只显示房间列表和创建界面，不会提前创建或显示棋盘。创建或加入房间并收到房间状态后，客户端才根据服务器下发的棋盘描述生成棋盘。

创建房间页面先选择“战役模式”或“对战模式”；战役模式暂未实现并禁用，对战模式下通过“地图”下拉选择具体战斗，当前提供“经典”和“突围”。“与人机对战”不再作为独立对战模式，而是位于默认折叠的“游戏参数”中，默认关闭；勾选后才会显示机器人难度。增援量与双方兵种上限分别收在“进攻方兵力设置”和“防守方兵力设置”中，并与“部署规则”一起统一放入“游戏参数”。

对手类型（玩家/机器人）与玩法模式使用不同字段：`gameMode` 表示对手类型，`variantId` 表示玩法。服务端从 `data/battle-catalog.json` 加载战斗目录，再通过每场战斗的 `battle.json` 读取地图、单位类型、地形类型、战斗规则、通用游戏规则、通用人机配置和可选的特殊规则。状态中仍下发兼容的 `variantId`、`boardId`、玩法信息和完整地图描述。对战模式目前提供经典和突围；无效或未启用战斗不会出现在大厅中，经典战斗无法加载时服务器拒绝启动。

单位定义和游戏规则同样由服务端随房间状态下发到 `rules` 字段。该字段包含单位名称、图标、移动/射程参数、单位免疫关系、地形可通行单位、地形攻击免疫、战斗和回合规则等。服务端同时计算并下发每个单位的 `selectable`、`legalMoves`、`legalShots` 以及当前玩家的 `legalDeployments`；前端只使用这些结果进行高亮和交互，不自行计算可选定、移动或攻击范围。移动、部署、射击、地形限制和胜负判定始终由服务端再次校验。规则缺失或格式非法时，前端不自行恢复规则，只显示安全的未知单位/地块占位并等待合法状态。

经典与突围中，双方都可以设置和部署反坦克炮、机枪车；部分地图的默认上限为 0，房主调高对应上限即可启用，默认兵力数值不变。

地图、类型和规则不是写死在核心代码中的定义，而是以分层 JSON 存放：

```text
data/
├── terrain-types/classic-terrain.json   # 地形身份和显示信息
├── unit-types/classic-units.json        # 单位身份和显示信息
├── maps/classic-six-rows.json           # 地形排列和格子连接
├── maps/breakout.json                   # 突围地图及显式连接表
├── combat-rules/classic-combat.json     # 移动、攻击和地形交互
├── game-rules/classic-game.json         # 部署、回合和胜负条件
├── ai-profiles/light-search.json         # 跨战斗复用的轻量搜索配置
├── battles/classic/battle.json          # 经典战斗资源入口
├── battles/breakout/                    # 突围入口和本场特殊规则
└── battle-catalog.json                  # 所有战斗的总入口
```

地形类型和单位类型只保存名称、图标、颜色等非实质信息。地图只依赖地形类型；战斗规则基于地形和单位定义移动、攻击及秒杀关系；通用游戏规则在战斗规则上定义部署、回合和胜利条件。当前经典战斗没有额外特殊规则，入口中的 `scenarioRules` 为 `null`。完整依赖、字段职责和扩展约定见 [`docs/data-structure.md`](docs/data-structure.md)。

`combat-rules/classic-combat.json` 的 `combat.instantKill` 用于定义直接击毁规则。攻击者必须属于 `attackerTypes`；目标属于 `targetTypes` 或目标所在的地形属于 `terrainTypes` 时触发。经典借此规定反坦克炮可直接击毁任意地形上的机枪车，以及堡垒内的步兵或反坦克炮。

经典和突围共用 `data/ai-profiles/light-search.json`。机器人在后端采用最多两层的有界前瞻搜索，会优先执行立即获胜和即时击杀，并综合考虑集火、进攻推进、防守封锁、地形、后续射击机会、机动空间和敌方火力威胁。每个难度都限制候选数、分支数、总节点数和单次计算时间；普通难度最多检查 24 个节点，单次预算为 6 毫秒。机器人只搜索服务端规则引擎给出的合法行动，不依赖固定地图行列。

前端收到地图后，会根据棋盘区域的实际宽度和当前视口可用高度计算显示比例。地图坐标、连接关系和服务端判定保持原尺寸，只有棋盘整体等比缩小；小于可用区域的地图不会放大。

难度分为三档：

- **简单**：在多个较高分动作中随机选择，忽略大部分站位风险。
- **普通**：在接近最优的动作中选择，并考虑基本威胁。
- **困难**：选择当前评分最高的动作，更重视敌方射程和机动空间。

所有难度都只评估当前合法动作，每个动作后重新读取局面，并通过定时器让出事件循环。单个机器人回合最多执行100步，避免极端自定义配置拖住服务器。

运行 `npm test` 可以检查机器人关键策略和前端脚本语法。

## 可选音效

音效目录位于 `public/audio/`。没有对应文件则不播放；同一目录有多个支持格式的文件时随机选择。

支持：`.mp3` `.wav` `.ogg` `.m4a` `.aac` `.webm` `.flac`

普通背景音乐从 `public/audio/bgm/` 选择后循环重播，自定义 BGM 同样循环。游戏结束音乐从 `public/audio/end/` 随机读取；当前示例文件为 `game-over.mp3`。游戏结束后先停止普通背景音乐，再播放一次结束音乐；结束音乐播放完毕后保持静音，不恢复普通 BGM。浏览器拒绝自动播放时，可在后续用户操作时重试。

对局中的“退出房间”会结束当前对局并将当前客户端返回大厅；另一方会收到对应的胜利状态。对局结束后，结果显示在棋盘下方横幅中，不再使用全屏结果弹窗。

## 同时回合制

经典可以在创建房间的“游戏参数”中启用同时回合制，默认关闭。双方在规划阶段分别保存部署、射击和移动计划；双方提交后，服务器按照“部署→同时射击→移除死亡单位→同时移动→胜负判定”结算。部署冲突和移动路径的中间格/最终格冲突都由服务器逐点随机决定，失败移动回到原点。具体能力和超时设置位于 `data/game-rules/classic-game.json` 的 `simultaneous` 节点，详细状态与扩展约定见 `docs/simultaneous-turns.md`。

机器人在自己的回合开始行动前，会像玩家一样连续部署所有当前合法且可用的单位，然后再执行移动和射击。开启“允许行动后部署”只会放宽玩家/机器人在行动后的部署限制，不改变机器人会优先完成部署阶段的行为。

```text
public/audio/
├── bgm/                         # 背景音乐，可放多个文件
├── move/
│   ├── infantry/                # 步兵移动
│   ├── anti-tank/               # 反坦克炮移动
│   └── machine-gun/             # 机枪车移动
├── attack/
│   ├── infantry/                # 步兵攻击
│   ├── anti-tank/               # 反坦克炮攻击
│   └── machine-gun/             # 机枪车攻击
└── death/
    ├── infantry/                # 步兵死亡
    ├── anti-tank/               # 反坦克炮死亡
    └── machine-gun/             # 机枪车死亡
```

浏览器通常禁止未经过用户操作的自动播放，因此背景音乐会在玩家第一次点击、触摸或按键后开始。
